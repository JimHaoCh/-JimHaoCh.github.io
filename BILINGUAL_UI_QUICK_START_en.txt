NE-501 v1.5.0 quick start

Manual Control: Connect & map > Syringe & tubing > Manual console.
Timeline Editor: Pumps & paths > Syringes > Timeline editor > Check & preview.

Enter the actual syringe inside diameter in mm and confirm tubing/outlet preparation. Set formal rate, units, direction and continuous or target-volume mode. Write & verify, then start on the pump card or fixed editor footer. Four cards retain Start/Resume and Stop while the editor scrolls. Editing a pump leaves the independently selected group unchanged.

Use the single Priming/purge tool for optional preparation. Choose one of five speeds or a custom rate, direction and finite volume. Write & verify, then explicitly start priming. Continue with formal delivery after priming defaults off and requires tubing confirmation. Formal start enters formal delivery directly. Resume retains native progress. Changed priming drafts require a new priming write; unchanged verified formal delivery remains available.

Single/group Stop stops the motor and preserves native progress. Resume delivery continues the remaining dose. A paused finite delivery also offers Restart a full dose. Stop all ends the program on every configured address and confirms responses individually. Invalid fields never disable Stop. A stop request cancels subsequent ordinary packets after the current communication response; hardware latency has not been measured.

The demo controller models elapsed-time finite delivery, pause/resume and explicit priming transitions. Demo mode identifies virtual pumps. Offline planning and Real pump connection identify the other connection categories. Cancelling example loading preserves mode, page and draft.

Flow preview sends no pump start commands. Initial preparation belongs in timeline blocks, and all included blocks contribute to totals. Drag, trim, copy, split, snap, undo/redo, unit conversion and JSON files remain available. Device read-backs and tubing confirmations are session data.

See BILINGUAL_MANUAL_UI_v1.5.0.md and UI_REVIEW_v1.5.0.md. Windows x64 and Windows 11 ARM64 share the installer. Automated device tests use simulated I/O; actual delivery, tubing behavior, stop latency and synchronization require hardware measurements.
